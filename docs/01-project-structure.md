# 01 — Project structure

There are six project shapes in the ecosystem. Five of them have a template in
[`templates/`](../templates/) (the static shape has two: plain and with docs); the split-repo shape
is simply two templates side by side. Start from the matching template so the layout is correct
from day one.

| Shape | Template | Port |
| --- | --- | --- |
| Backend service | [`backend-service`](../templates/backend-service/) | 12500 |
| Nuxt app | [`nuxt-app`](../templates/nuxt-app/) | 12510 |
| Split repo | `backend-service` + `nuxt-app` | 12500 + 12510 |
| Full-stack Nuxt app | [`fullstack-nuxt-app`](../templates/fullstack-nuxt-app/) | 12520 |
| Static site | [`static-site`](../templates/static-site/), [`static-site-with-docs`](../templates/static-site-with-docs/) | 12530, 12531 |
| CLI tool | [`cli-tool`](../templates/cli-tool/) | — |

The trees below list what the templates ship (generated folders such as `node_modules/`,
`.nuxt/`, `.output/`, `build/`, `data/` and `app/api-client/` contents are omitted).

## Backend service (Hono + Zod + OpenAPI + Drizzle)

```
my-service/
├── src/
│   ├── index.ts                    # `Main` — lifecycle + inline graceful shutdown (self-invoked)
│   ├── api/
│   │   ├── index.ts                # `API` static class: init/start/stop/getApp — CORS, onError, docs, /health
│   │   ├── utils/
│   │   │   ├── api-res.ts          # `APIResponse` — envelope helpers + Schema/Utils/Types
│   │   │   ├── apiVersionRouter.ts # `APIVersionRouter` base class
│   │   │   ├── authHandler.ts      # AuthUtils, SessionHandler, APIKeyHandler, AuthHandler
│   │   │   ├── specHelpers.ts      # `APIRouteSpec` / `APIResponseSpec`
│   │   │   ├── email.ts            # `EmailService` (nodemailer)
│   │   │   ├── metadata.ts         # runtime metadata (key/value table)
│   │   │   ├── preferences.ts      # user preferences
│   │   │   └── shared-models/{accountData,api-helper-models}.ts
│   │   └── versions/v1/
│   │       ├── index.ts            # `APIv1Router` — openAPIConfig + one router (auth middleware, mounts routes)
│   │       ├── docs/index.ts       # `DOCS_TAGS`
│   │       ├── middleware/auth.ts  # `authMiddlewareV1`
│   │       └── routes/
│   │           ├── auth/{index,model}.ts        + reset-password/{index,model}.ts
│   │           ├── account/{index,model}.ts     + apikeys/{index,model}.ts, preferences/{index,model}.ts
│   │           └── admin/index.ts               + users/{index,model}.ts
│   ├── db/{index,schema,utils}.ts  # `DB` (DB.Tables / DB.Models) + Drizzle schema + SQLUtils
│   ├── tasks/{index,sampleTask,utils}.ts        # `TaskScheduler` — persisted background tasks
│   └── utils/
│       ├── config.ts               # `ConfigHandler` + `CS` schema builder
│       ├── constants.ts            # `AppConstants` (APP_NAME, APPPREFIX/appprefix, BINARY_NAME)
│       ├── cron.ts                 # `CronJobHandler`
│       ├── index.ts                # `Utils`
│       ├── logger.ts               # `Logger`
│       └── crypto/{cryptoKeys,lcrypt,objectCrypt,signature}.ts
├── drizzle/
│   ├── configs/drizzle.config.ts
│   └── migrations/                 # generated by `bun run db:generate` (commit them)
├── scripts/
│   ├── compile/{index,compileCMD,compiler}.ts   # `bun run compile <target>`
│   ├── entrypoint.ts               # sets APPPREFIX_DB_AUTO_MIGRATE=true, imports src/index
│   └── db-utils.ts                 # ensures ./data/ exists before drizzle-kit runs
├── tests/
│   ├── api-routes-v1.test.ts  email.test.ts
│   └── helpers/{api,preload,seed,memory-transport}.ts
├── docker/{Dockerfile, docker-compose.yml}      # binary + drizzle/migrations on debian:stable-slim
├── tsconfig.json  tsconfig/{tsconfig.base,tsconfig.typecheck}.json
├── package.json  bun.lock  bunfig.toml  biome.json  example.env  .gitignore
├── .claude/settings.json
├── .gitlab-ci.yml  .gitlab/{ci/{testing,build}.yml, renovate.json}
└── LICENSE  README.md  AGENTS.md  CLAUDE.md
```

Key rules: one folder per resource under `routes/`, each with `index.ts` (the router, `export
const router = new Hono().basePath("/<resource>")`) and `model.ts` (the Zod schemas).
Sub-resources are sub-folders mounted by their parent with
`router.route("/", (await import("./reset-password")).router)`. Versioned routers live under
`versions/v{n}/`. The `API` class is a static singleton with `init`/`start`/`stop`/`getApp`. See
[04](04-backend-hono.md).

The backend has **no** GitHub workflow and **no** `.vscode/mcp.json`. `data/` and `config/` are
runtime directories (gitignored); the template ships no `config/*.example.json`.

## Nuxt app (NuxtUI v4 + Tailwind v4)

```
my-app/
├── app/                            # Nuxt 4 srcDir — everything lives here
│   ├── app.vue  app.config.ts  error.vue
│   ├── assets/css/main.css         # @import "tailwindcss"; @import "@nuxt/ui"; @theme {…}
│   ├── api-client/                 # GENERATED by @hey-api/openapi-ts — never hand-edit
│   ├── components/
│   │   ├── Gravatar.vue
│   │   ├── dashboard/{DashboardPageHeader,DashboardPageBody,DashboardModal,DashboardDeleteModal,DataTable,UserMenu}.vue
│   │   ├── form/DateRangePicker.vue
│   │   ├── img/{AppLogo,AppIcon}.vue
│   │   └── layout/{Header,Footer}.vue
│   ├── composables/
│   │   ├── stores/{useUserStore,useOnboardingStore}.ts
│   │   ├── useAPI.ts  updateAPIClient.ts  useAppCookies.ts  useRuntimeAppConfigs.ts
│   │   ├── useAwaitedComputed.ts  usePageSeo.ts  useDefaultOnFormError.ts  useGravatarURL.ts
│   │   └── useSubrouterInjectedData.ts  useSubrouterPathDynamics.ts
│   ├── layouts/{default,auth,dashboard,onboarding}.vue
│   ├── middleware/{auth.global,rewrites.global}.ts
│   ├── pages/
│   │   ├── index.vue  welcome.vue
│   │   ├── auth/{login,signup,forgot-password,reset-password}.vue
│   │   └── dashboard/
│   │       ├── index.vue  settings.vue  settings/{index,security}.vue

│   │       └── admin/users.vue
│   └── utils/{abstractStore,routeMatcher,format,roles,types,url}.ts
├── public/{favicon.ico, robots.txt, static/logo/icon.{png,svg}, static/utils/sitemap.xml}
├── scripts/{api-client-generate,patch-api-client}.ts   # api-client generation + patch (see 05)
├── tests/basic.test.ts

├── nuxt.config.ts  openapi-ts.config.ts
├── tsconfig.json  tsconfig/tsconfig.typecheck.json
├── package.json  bun.lock  biome.json  example.env  .gitignore
├── .claude/settings.json  .vscode/mcp.json

└── LICENSE  README.md  AGENTS.md  CLAUDE.md
```

The Nuxt 4 `app/` srcDir is mandatory. API access goes through `useAPI` (never raw `$fetch`); state
through `AbstractStore` over `useState`. This shape has **no `server/`** — the frontend talks to a
separate backend service over HTTP. The template is a complete app shell (landing page, auth,
onboarding, dashboard, API keys, admin users); delete what the project doesn't need. See
[06](06-frontend-nuxt.md) and [07](07-state-and-data.md).

## Split-repo (backend + frontend in separate repos)

When the backend and frontend are owned and deployed independently, keep them in **two repos** — a
backend service + a Nuxt app — and let the backend's OpenAPI spec be the contract between them.
Delivr (`Delivr-API` + `Delivr-Web`) and LeiOS (`API-Server` + `Hub-Website`) use this shape.

```
my-org/
├── my-service-api/        # the backend-service shape (port 12500)
│   └── … serves /docs/v1/openapi (docs enabled)
└── my-service-web/        # the nuxt-app shape (port 12510)
    ├── openapi-ts.config.ts   # input: "http://localhost:12500/docs/v1/openapi"
    └── example.env            # APPPREFIX_API_URL=http://localhost:12500
                               # APPPREFIX_APP_URL=http://localhost:12510
```

Rules:

- The frontend's `openapi-ts.config.ts` `input` is the **live** backend spec
  (`http://localhost:12500/docs/v1/openapi`), so the backend must be running with its docs enabled
  (`APPPREFIX_API_DISABLE_DOCS` unset or `false`) when you run `bun run api-client:generate`
  (`scripts/api-client-generate.ts` → `openapi-ts` + patch). See
  [05 — API contract](05-api-contract.md).
- `APPPREFIX_API_URL` configures the backend origin (the Nitro banner maps it to
  `NUXT_PUBLIC_API_URL` at runtime, so the `NUXT_PUBLIC_*` spelling is only an override);
  `updateAPIClient` sets the SDK `baseURL` to `<apiUrl>/v1`.
- The backend's `APPPREFIX_APP_URL` is the frontend origin (`http://localhost:12510` in
  `example.env`). It is the CORS allowlist (`credentials: true`, preflight `maxAge: 600`) and the
  base of the password-reset links.
- Each repo has its own `AGENTS.md` / `CLAUDE.md` pointing at this guide plus repo-specific notes.
  The backend owns the Zod schemas and the envelope; the frontend consumes the generated SDK.
- Bump the contract deliberately: change a backend route + schema, regenerate the client, commit the
  regenerated `app/api-client/` in the frontend repo.

A split-repo project is just `backend-service` + `nuxt-app` side by side, with no changes. See
[17 — Decisions › Split-repo and full-stack Nuxt are both first-class](17-decisions.md#13-split-repo-and-full-stack-nuxt-are-both-first-class).

## Full-stack Nuxt app (Nuxt + Hono in `server/`)

When the backend is small enough to live with the frontend, mount Hono inside Nitro and let it own
the `/api` endpoint. Status-Page and MindCode use this shape. Everything from the Nuxt app shape
applies, plus a `server/` directory whose `lib/` mirrors the standalone backend's `src/` — but
without `Main` or `API.start()`: Nitro owns the HTTP server and the lifecycle.

```
my-app/
├── app/                            # same as the Nuxt app shape, except updateAPIClient.ts (<appUrl>/api/v1)
├── server/
│   ├── routes/api/[...].ts         # catch-all → Hono app mounted at /api (503 while the API is starting)
│   ├── plugins/startup.ts          # Nitro plugin: config → DB → tasks → email → cron → API.init; `close` hook shuts down
│   └── lib/
│       ├── api/                    # same layout as backend-service src/api/ (index.ts, utils/, versions/v1/…)
│       ├── db/{index,schema,utils}.ts
│       ├── tasks/{index,sampleTask,utils}.ts
│       └── utils/{config,constants,cron,index,logger}.ts + crypto/
├── drizzle/{configs/drizzle.config.ts, migrations/}
├── scripts/
│   ├── api-client-generate.ts      # in-process: API.init → /docs/v1/openapi → openapi-ts
│   ├── patch-api-client.ts         # post-generation patch on sdk.gen.ts / client/client.gen.ts (see 05)
│   ├── db-utils.ts
│   └── compile/  entrypoint.ts     # present, not wired to a script; no working binary (see 14)
├── tests/
│   ├── api-routes-v1.test.ts  email.test.ts
│   └── helpers/{api,preload,seed,memory-transport}.ts
├── public/{favicon.ico, robots.txt, static/logo/icon.{png,svg}, static/utils/sitemap.xml}
├── docker/{Dockerfile, docker-compose.yml}      # oven/bun:1-slim + .output/ + drizzle/migrations
├── nuxt.config.ts  openapi-ts.config.ts  bunfig.toml
├── tsconfig.json  tsconfig/tsconfig.typecheck.json
├── package.json  bun.lock  biome.json  example.env  .gitignore
├── .claude/settings.json  .vscode/mcp.json
├── .github/workflows/ci.yml
├── .gitlab-ci.yml  .gitlab/{ci/{testing,build}.yml, renovate.json}
└── LICENSE  README.md  AGENTS.md  CLAUDE.md
```

The relevant `nuxt.config.ts` bits:

```ts
nitro: {
	rollupConfig: {
		external: ["bun:sqlite"],

		output: {
			banner: (function () {
				const mappings = {
					APPPREFIX_APP_URL: "APP_URL",
				};

				const bannerCode = `
					(function () {
						const mappings = ${JSON.stringify(mappings)};
						const env = globalThis.process?.env ?? {};
						for (const [envName, runtimeName] of Object.entries(mappings)) {
							if (!env['NUXT_PUBLIC_' + runtimeName] && env[envName]) {
								env['NUXT_PUBLIC_' + runtimeName] = env[envName];
							}
						}
					})();
				`;

				return bannerCode.replace(/^\s+|\s+$/g, "").replace(/\n\s*/g, " ");
			})(),
		},
	},

	esbuild: {
		options: {
			target: "esnext",
		},
	},
},

runtimeConfig: {
	public: {
		//@ts-ignore
		appUrl: process.env.APPPREFIX_APP_URL || "http://localhost:12520",
	},
},
routeRules: {
	"/dashboard/**": { ssr: false },
	"/auth/**": { ssr: false },
	"/**": { ssr: true },
},
```

The contract: Hono is mounted at `/api`, so endpoints are `/api/v1/<resource>`, `/api/health`,
`/api/docs/v1` (bare `/api` is not routed — the Nitro catch-all needs `/api/...`). The frontend's
`updateAPIClient` sets `baseURL` to `<appUrl>/api/v1` (same origin). The config has no
`API_HOST`/`API_PORT` — the port is the Nitro one. See
[04 — Backend › Mounting Hono in Nitro](04-backend-hono.md#mounting-hono-in-nitro) and
[05 — API contract](05-api-contract.md).

```
├── package.json  bun.lock  biome.json  .gitignore
```

No `useAPI`, `api-client/`, `auth.global.ts`, `AbstractStore` or `server/` — this shape has no
backend and no `example.env`. Every page calls `usePageSeo`; `robots.txt` and
`static/utils/sitemap.xml` are hand-written; `public/.htaccess` configures Apache. Deploy with
`bun run generate` + rsync (see [14](14-deployment.md)).

### Variant: static site with docs

[`static-site-with-docs`](../templates/static-site-with-docs/) is the static site plus a Markdown
docs section powered by `@nuxt/content`. It adds:

```
my-site/                            # everything from static-site, plus:
├── content/docs/{index,getting-started,about}.md    # the docs pages (Markdown + MDC)
├── content.config.ts               # `docs` collection: source "docs/**/*.md"
└── app/
    ├── pages/docs/[...slug].vue    # queryCollection("docs") + <ContentRenderer> (prose prose-invert)
    ├── components/docs/DocsPage.vue        # sidebar + prev/next
    ├── components/content/IconCardGrid.vue # MDC component usable inside Markdown
    └── data/docs.ts                # docs navigation — register every page here
```

Differences from `static-site`: `modules: ["@nuxt/ui", "@nuxt/content"]`; prerendering crawls links
(`crawlLinks: true`) and ignores `/__nuxt_content/**`; dev port 12531; its `biome.json` turns
`noUnusedImports`/`noUnusedVariables` off. When you add or remove a page in `content/docs/`,
update `app/data/docs.ts`.

```
my-cli/
├── src/
│   ├── index.ts                    # CLIApp: global --log-level flag, command registration, .handle(…, "shell")
│   ├── commands/{version-cmd,hello-cmd}.ts    # CLIBaseCommand subclasses
│   └── utils/{constants,logger}.ts            # AppConstants (BINARY_NAME), CLI Logger
├── scripts/
│   ├── compile/{index,compileCMD,compiler}.ts # `bun run compile <target|auto|all>` (bytecode on)
│   └── entrypoint.ts               # import "../src/index"
├── tests/basic.test.ts
├── tsconfig.json  tsconfig/{tsconfig.base,tsconfig.typecheck}.json
├── package.json  bun.lock  biome.json  .gitignore
├── .claude/settings.json
├── .github/workflows/{ci,release}.yml         # release: `v*` tag → binaries on a GitHub Release
├── .gitlab-ci.yml  .gitlab/{ci/testing.yml, renovate.json}   # GitLab build include is commented out
```

CLI tools compile to a single binary (`bun build --compile`) and are distributed via GitHub
Releases or baked into a Docker image. Add domain modules under `src/` as the tool grows. See
[11](11-cli-and-infra.md).

## Cross-cutting files

Every template carries:

- `.claude/settings.json` — slash commands + `fileScan.exclude`, plus `mcpServers` on the Nuxt-based
  shapes (copied from `shared/config/claude-settings.<shape>.json`). `.vscode/mcp.json` (the
  `nuxt` + `nuxt-ui` MCP servers) exists only on the Nuxt-based shapes. See
  [16](16-ai-tooling.md).
- `CLAUDE.md` + `AGENTS.md` — per-repo architecture notes and the AI operating manual.
- TypeScript config — see [02](02-tooling.md#typescript):
  - backend-service / cli-tool: `tsconfig.json` = `{ "extends": "./tsconfig/tsconfig.base.json" }`
    plus `tsconfig/tsconfig.typecheck.json` for the `tsc` pass.
  - Nuxt shapes: `tsconfig.json` is Nuxt's `.nuxt/tsconfig.*.json` references stub, and
    `tsconfig/tsconfig.typecheck.json` extends `../.nuxt/tsconfig.json` (from
    [`shared/tsconfig/tsconfig.typecheck.nuxt.json`](../shared/tsconfig/tsconfig.typecheck.nuxt.json)).
- `biome.json` — the formatter/linter (from [`shared/config/biome.json`](../shared/config/biome.json)) —
  see [02](02-tooling.md#biome-formatter--linter).
- CI — GitHub `.github/workflows/ci.yml` (all but backend-service) and GitLab `.gitlab-ci.yml` +
  `.gitlab/ci/` (all). See [13](13-git-and-ci.md).
- `.gitlab/renovate.json` — the minimal Renovate config (just `$schema`) — see
  [13](13-git-and-ci.md).
- `LICENSE` (AGPL-3.0), `README.md`, `.gitignore`, `package.json` + `bun.lock`.
- `example.env` only where the app reads environment variables: backend-service,
  fullstack-nuxt-app and nuxt-app. Static sites and the CLI template have none. The real `.env` is
  gitignored.

> In this style-guide repo, the templates' `bun.lock` and `drizzle/migrations/` are gitignored so
> they don't drift here. Real projects **commit both** (run `bun run db:generate` first).

Default branch is `main`. `master` exists only on legacy repos and should not be chosen for new
ones.
